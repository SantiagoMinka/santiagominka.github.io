§1

Physical clocks

Core idea. Computer clocks are timers that drift (ρ ≈ 10−6 s/s). Two clocks drifting in opposite directions grow apart by 2ρΔt, so to keep the skew below δ you must resynchronize every δ/2ρ seconds. Goals: accuracy (close to UTC) or agreement (close to each other). Time must never run backwards.

Q1CompareExam 14 Feb 2024 · 6 Sep 2024 · 13 Feb 2015 · 23 Sep 2015

Describe and compare the various approaches to synchronize the clocks of the nodes of a distributed system.

Model answer

  • GPS. A receiver gets timestamps from 4 satellites with atomic clocks. Four equations (distance = c × (Tnow − Ti + Δr)) give four unknowns: x, y, z and the clock deviation Δr. Accuracy: tens of nanoseconds. Needs a receiver with sky view.
  • Cristian. A client asks a time server (with UTC) and sets T = CUTC + Tround/2, where Tround = T1 − T0 − I (I = server processing time). Average several measurements. Never move the clock backwards: slow it down gradually. Accuracy depends on the round-trip symmetry.
  • Berkeley. The server is active: it polls all machines, averages their times, and sends each one the adjustment. It gives agreement, not accuracy (no UTC source needed).
  • NTP. Internet scale, over UDP, hierarchical strata (stratum 1 = connected to UTC). Modes: multicast (LAN), procedure-call (like Cristian), symmetric. From a pair of messages it computes the offset estimate oi = (Ti−2 − Ti−3 + Ti−1 − Ti)/2 and the delay di; the true offset is in [oi − di/2, oi + di/2]. Accuracy: ~1 ms on a LAN, 1–50 ms on the Internet.

Why

All message-based methods have the same limit: the unknown transmission delay. They estimate it as half the round trip, so the error is at most half the round trip. NTP improves this by filtering many samples and picking the one with the smallest delay. GPS avoids it, because satellites send from known positions and the receiver solves for its own clock error.

Q2ScenarioExam 14 Feb 2024

You correlate readings of geographically distributed vibration sensors to locate the origin of an earthquake with a precision below 1 km. Seismic waves travel at most at 10 km/s. Which clock synchronization approach would you use and why?

Model answer

1 km at 10 km/s is 0.1 s = 100 ms. The location comes from the differences of arrival times, so the clock error between any two sensors must be well below 100 ms (say ≤ 10 ms to keep a margin, since errors add up).

  • NTP over the Internet gives 1–50 ms: borderline, and not guaranteed.
  • Berkeley gives only agreement inside a LAN; sensors are far apart.
  • GPS gives tens of nanoseconds everywhere, and the sensors are outdoors anyway. It is the right choice. NTP can be the fallback if a sensor loses the GPS signal.

Why

Always convert the requirement into a time bound first: distance precision ÷ speed = allowed clock error. Then compare the bound with the accuracy of each method. This turns an open question into a calculation.

Q3Exercise

Quartz clocks drift at most ρ = 10−6 s/s. You need a maximum skew δ = 2 ms between any two machines. How often must you resynchronize? Why does Cristian's algorithm not set the clock back directly?

Model answer

Two clocks drifting in opposite directions diverge by 2ρΔt. Require 2ρΔt ≤ δ: Δt ≤ δ/(2ρ) = 0.002 / (2 × 10−6) = 1000 s (about 17 minutes).

Setting a clock back makes time run backwards: a file created later could get an older timestamp (the make problem). Instead, slow down the clock: e.g. advance it 9 ms instead of 10 ms per tick until it is correct. Monotonicity is preserved.

Why

The factor 2 is the trap: the bound is on the difference between two clocks, and each one can drift ρ in a different direction.

§2

Logical clocks

Core idea. Often you need only the order of events, not the real time. Happens-before (→): same process order, send → receive, transitive. Scalar clocks give e → e′ ⇒ L(e) < L(e′). Vector clocks give the equivalence: e → e′ ⇔ V(e) < V(e′).

Q4DescribeExam 12 Jul 2024 · 13 Jul 2015 · 3 Dec 2014 · 19 Sep 2013

Describe scalar clocks and how they can be used to implement a totally ordered multicast. Clarify the assumptions required for the protocol to work.

Model answer

Scalar clocks (Lamport). Each process keeps Li = 0. Increment it before each event; timestamp each message with Li; on receipt set Li = max(ts, Li) + 1. Ties are broken with the process id, which gives a total order (L.i).

Totally ordered multicast.

  1. The sender multicasts the message, with its timestamp, to all members, itself included.
  2. Each receiver puts the message in a local queue ordered by timestamp, and multicasts an ack (also timestamped) to all.
  3. A process delivers the message at the head of its queue only when it has received the acks for it from all processes.

All queues eventually contain the same messages in the same timestamp order, so all processes deliver in the same order.

Assumptions: reliable channels, FIFO channels, no process failures, known group.

Why

Why the acks: when P has an ack from Q with timestamp larger than m's, FIFO guarantees that no earlier message from Q (with a smaller timestamp) is still on the way. With acks from everybody, nothing with a smaller timestamp can arrive later, so the head of the queue is final. Without FIFO, an older message could arrive after a newer ack. Without reliability or with crashes, a missing ack blocks delivery forever.

Exam tip

Example to cite: a replicated bank account. Deposit $100 and add 1% interest. If the replicas apply them in different orders, they get $1111 vs $1110.

Q6Exercise

Three processes run a distributed algorithm. At the end their vector clocks are P1: (4, 5, 6), P2: (5, 6, 6), P3: (3, 2, 7). Is this possible? Why?

Model answer

No. Vi[i] is the number of events at Pi, and Vj[i] is the number of events of Pi that Pj knows. Nobody can know more events of Pi than Pi itself: Vj[i] ≤ Vi[i]. Here V2[1] = 5 > V1[1] = 4. Impossible.

The other entries are fine: P1 knows 5 ≤ 6 events of P2 and 6 ≤ 7 events of P3; P3 knows 3 ≤ 4 and 2 ≤ 6.

Why

Check the columns: in column i, the diagonal element must be the maximum. Information about Pi's events can only come from Pi.

Q7DescribeExam 9 Sep 2015

Why do we need vector clocks if we have scalar clocks? Describe an algorithm that uses vector clocks: causal delivery of messages (e.g. a bulletin board).

Model answer

Scalar clocks: e → e′ ⇒ L(e) < L(e′), but L(e) < L(e′) does not imply e → e′. You cannot tell if two events are concurrent. Vector clocks give e → e′ ⇔ V(e) < V(e′), and e ∥ e′ ⇔ neither vector is ≤ the other.

Causal delivery. Messages and replies are multicast over reliable FIFO channels. Only replies must follow their messages; total order is too strong. Variant of vector clocks: increment Vi[i] only when sending; on receipt just merge. Pk delivers a message r from Pj only when:

  • ts(r)[j] = Vk[j] + 1 (it is the next message from Pj), and
  • ts(r)[i] ≤ Vk[i] for all i ≠ j (Pk has seen everything Pj had seen).

Otherwise Pk holds r until the missing messages arrive.

Why

The second condition is the core: if the reply's timestamp shows that its sender had seen message m from Pi, but Pk has not seen m yet, delivering the reply would show an answer before its question.

§3

Mutual exclusion and leader election

Core idea. Mutual exclusion needs safety (at most one process in the critical section) and liveness (no deadlock, no starvation); optionally happened-before ordering. Election makes all live processes agree on the live process with the highest id.

Q8DescribeExam 18 Jun 2024 · 19 Feb 2013

Describe the problem of mutual exclusion and how you could solve it using scalar clocks. Which properties does this protocol satisfy? Under which assumptions does it operate correctly?

Model answer

Problem. Processes share a resource without shared memory. Requirements: safety, liveness, and optionally ordering (if request 1 happened before request 2, grant 1 first).

Protocol (Ricart–Agrawala style, from the slides).

  1. To request, Pi multicasts a request with timestamp Tm to all processes.
  2. A receiver Pj:
    • not holding and not interested → sends an ack at once;
    • holding the resource → queues the request;
    • also requesting → compares timestamps: if Tm is lower (ties broken by id) it acks, else it queues.
  3. Pi enters when it has acks from all other processes.
  4. On release, Pi acks all queued requests.

Properties. Safety: two processes cannot both get all acks, because the one with the larger timestamp waits. Liveness: timestamps give a total order, so no cycle of waiting (no deadlock) and every request eventually becomes the smallest (no starvation). Ordering: if req1 → req2 then T1 < T2, so req1 is served first.

Assumptions. Reliable channels and reliable processes; all processes known. Cost: 2(n − 1) messages per entry. Any crash blocks everybody: n points of failure instead of one.

Why

The scalar clock plus process id is a total order that all processes compute the same way. So every conflict between two requests is resolved identically everywhere, without a coordinator.

Q9CompareExam 25 Feb 2015

Describe and compare the techniques to guarantee mutual exclusion when accessing a remote resource.

Model answer

  • Centralized: a coordinator holds a token; request, grant, release messages. Simple and fair.
  • Distributed with scalar clocks: the previous question.
  • Token ring: processes form a logical ring; a token circulates; you may use the resource only while holding the token.

Q10Compare

Compare the bully and the ring election algorithms: number of messages, assumptions, and how easy it is to guarantee the assumptions.

Model answer

Bully. P sends ELECT to all higher ids. If nobody answers, P wins and sends COORD to all lower ids. A process that gets ELECT answers (stops the sender) and starts its own election. A recovered process holds an election and wins if it has the highest id. Messages: O(n²) in the worst case (the lowest id starts), n − 2 + … in the best case (the second highest starts). Assumptions: reliable links and a synchronous system, to decide that "nobody answers" means crashed.

Ring. P sends ELECT with its id to the next live neighbor. Each process adds its id and forwards. When the message comes back to a process already in the list, it becomes COORD and goes around once more; the highest id is the leader. Messages: 2n per election (more if several start). Assumptions: a ring topology and the ability to skip dead neighbors (also a form of failure detection).

Both need failure detection, so both rely on timeouts. The ring needs fewer messages but is slower (sequential), and a crash during the election must be handled.

Why

Both algorithms assume a closed system: processes know each other's ids, but not who is alive. The difficult assumption is always "detect who crashed", which is impossible in an asynchronous system (chapter 02).

Global state and termination

Core idea. The global state is the local states plus the messages in transit. With no global clock, record a consistent cut: if a receive is in the cut, the send must be too. Chandy–Lamport does it with markers (tokens), without stopping the computation.

Q12Describe

Describe the Chandy–Lamport snapshot algorithm and prove that it selects a consistent cut.

Model answer

Assumptions: FIFO reliable channels, reliable processes, strongly connected graph.

  • The initiator records its state, sends a token on every outgoing channel, and starts recording all incoming channels.
  • On a token on channel c: if the process has not recorded yet, it records its state, sends tokens on all outgoing channels, and starts recording all other incoming channels; channel c is recorded as empty. In any case, it stops recording c.
  • A message that arrives on a channel being recorded is added to that channel's record, then processed normally.
  • A process is done when it has a token on every incoming channel. The results go to a collector.

Proof. Take ei → ej, with ej in the cut. Suppose ei is not in the cut: pi recorded its state before ei, so it sent its tokens before ei, and before the messages m1…mh that create the chain ei → ej. By FIFO and the token rule, each process along the chain receives a token before those messages, so pj records its state before ej. Contradiction: ej would not be in the cut.

Why

The token is a separator in each FIFO channel: everything before it was sent before the sender's snapshot, everything after it was sent after. This is why FIFO is essential. The algorithm does not block the computation; concurrent snapshots are told apart with an id set by the initiator.

Q13Compare

How do you detect termination of a distributed computation? Compare the snapshot-based approach with Dijkstra–Scholten.

Model answer

Termination: all processes idle and no messages in transit.

Snapshot-based (Tanenbaum). The predecessor of p is the process that sent p its first marker. When p finishes its part, it sends DONE to its predecessor only if all its successors sent DONE and p received no message between recording its state and getting markers on all incoming channels. Otherwise CONTINUE. If the initiator gets only DONE, the computation is over; otherwise run another snapshot. Cost: one message per link plus collection, repeated until success.

Dijkstra–Scholten (diffusing computations: one initiator, processes activated only by messages). Build a tree of active processes: a process woken by a message becomes the child of the sender; if it was already active, it acks at once. An idle leaf leaves the tree and notifies its parent. When only the idle root remains, the computation is over. Cost depends on the number of application messages; never-activated processes are not involved; termination is detected as soon as the last ack arrives.

Why

The snapshot approach checks periodically and may need many runs. Dijkstra–Scholten tracks the computation continuously, so it detects termination at once, but it costs one ack per message.

§5

Distributed transactions and deadlocks

Core idea. Transactions are ACID. Atomicity uses a private workspace or a write-ahead log. Isolation needs a scheduler: locks (2PL) or timestamps (pessimistic or optimistic). Deadlocks can be ignored, detected, or prevented.

Q14ScenarioExam 18 Nov 2023

Describe pessimistic timestamp ordering: which problem does it address and how does it work? In a system with few requests per second and a large dataset, would you use pessimistic or optimistic timestamp ordering, and why?

Model answer

Problem: concurrency control (isolation/serializability) of transactions without locks, and so without deadlocks.

How it works. Each transaction T gets a timestamp ts (e.g. from logical clocks). Writes create tentative versions xi with tswr(xi) until commit. Each item keeps tsrd(x) and the committed tswr(x).

  • write(T, x): if ts > tsrd(x) and ts > tswr(x), make a tentative write; else abort T (it arrives too late).
  • read(T, x): if ts > tswr(x), select the latest version with write timestamp < ts. If it is committed, read it and set tsrd(x) = max(ts, tsrd(x)); else wait for that writer to commit or abort. If ts < tswr(x), abort T.
  • Aborted transactions restart with a new timestamp. No deadlock: waits go only from younger to older.

Choice: optimistic. Few requests over a large dataset means conflicts are rare. Optimistic ordering lets transactions run freely in private workspaces and checks for conflicts only at commit, so it has no checking overhead during execution and maximum parallelism. Rollbacks would be expensive only under heavy load with many conflicts, which is not the case here.

Why

The choice depends on the probability of conflict. Pessimistic methods pay a cost on every operation to prevent conflicts; optimistic methods pay only when a conflict really happens. Rare conflicts → optimistic wins.

Q15Describe

Describe two-phase locking and strict 2PL. What are centralized, primary and distributed 2PL?

Model answer

2PL. A transaction asks the scheduler for a lock before each access; conflicting operations (read-write, write-write) wait. Once T releases a lock, it can no longer acquire any (growing phase, then shrinking phase). 2PL guarantees serializability but can deadlock.

Strict 2PL: release all locks together, after the transaction ends. This prevents cascaded aborts (nobody reads uncommitted data).

  • Centralized 2PL: one lock manager; the transaction manager gets locks there and talks to the data managers directly.
  • Primary 2PL: each data item has a primary copy; the lock manager on that host grants its locks.
  • Distributed 2PL: data may be replicated; the lock manager on each host grants locks on its local replica and talks to the local data manager.

Why

The two phases guarantee that each transaction has a "lock point" where it holds all its locks; ordering transactions by lock points gives an equivalent serial schedule.

Q16Compare

Compare centralized deadlock detection, Chandy–Misra–Haas, and the wait-die / wound-wait prevention schemes.

Model answer

Centralized detection. Each machine sends its wait-for graph to a coordinator (on every change, periodically, or on demand). Problem: false deadlocks, because updates from different hosts can arrive in an inconsistent order.

Chandy–Misra–Haas. A blocked process sends a probe (initiator, sender, receiver) to the holders of the resources it wants; they forward it. If the probe returns to the initiator, there is a cycle. Recovery: the initiator kills itself (several initiators may kill too many), or the probe collects ids and the highest id is killed.

Prevention with global timestamps. Wait-die: an older process may wait for a younger one; a younger one that wants a resource held by an older one dies. Wound-wait (preemption): an older process preempts (wounds) a younger holder; a younger process waits for an older one. In both, waits follow timestamps in one direction, so no cycle. Wound-wait avoids the repeated deaths of young processes of wait-die.

Why

A cycle needs a wait in both directions of age. Allowing waits only from old to young (or only young to old) breaks every possible cycle. Transactions make killing acceptable: an abort is a clean rollback.
